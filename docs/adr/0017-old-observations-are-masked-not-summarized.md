# 历史观察被掩蔽，不被摘要也不被丢弃

[ADR-0001](./0001-messages-are-the-single-source-of-truth.md) 定了消息表存**完整**的模型视角序列、每轮重建，并在「后果」里把这件事挂了起来：「存了完整序列」不等于「每轮把完整序列喂给模型」。本 ADR 回答它挂起的那个问题。

膨胀的来源不是对话文本，是工具结果正文——一轮 `web_reader` 的返回可能是同轮用户消息的几百倍。而会话[全局公开共享、任何访客可续聊](./0013-the-session-list-shows-business-facts-only.md)，增长**没有自然终点**：这不是「某个重度用户的长会话」，是结构性无界，且失败模式是硬的（超窗直接报错，不是慢慢变差）。

**决定：压缩分三层，永远优先最轻的干预；主力手段是[观察掩蔽](../../CONTEXT.md)——保留最近 N 对工具调用与结果的完整正文，更早的工具结果只留指代。**

| 层 | 机制 | 触发 |
|---|---|---|
| 第 0 层 | [渐进披露](../../CONTEXT.md) + 一份结果两个出口 | 单次工具返回超阈值（[ADR-0005](./0005-long-documents-use-progressive-disclosure.md)、[ADR-0004](./0004-tools-are-capabilities-providers-are-implementations.md)，本 ADR 不动） |
| 第 1 层 | **观察掩蔽** | 常态 |
| 第 2 层 | 丢弃已完成运行的整块 | 失败的持久后果（见下） |
| — | 任何形式的摘要 | **不做** |

## 第 1 层：一个不分运行边界的滑动窗口

最近 N 对工具调用/结果保留完整正文，更早的一律掏空。窗口横跨运行边界自然滑动——本轮已产生 N 对时历史全被掏空，本轮只有一对时窗口吃进历史 N-1 对。**因此不存在「运行内」与「跨运行」两套机制，一条规则覆盖两处。**

掏空**保留工具调用的入参**，只把结果内容换成结构化指代：工具名、入参、来源标题与 URL，不留正文。模型仍看得见「第二轮我搜过什么、拿到了哪几个来源」。

**它天然绕开一条硬约束。** 掏空不制造悬空工具调用——结果消息还在，只是内容变了，配对关系不破。[ADR-0008](./0008-a-run-emits-domain-events-not-wire-frames.md) 的悬空修复本是给「运行中途断掉」准备的异常路径，本设计不需要它去兜常态路径。

**掏空是净收益，不是妥协。** 方向与 ADR-0005 引的 Context Rot 一致：少喂无关正文，模型更准。业界实测（Anthropic 公布其 context editing 在 agentic search 上 +29%）指向同一侧。掏空是在同一方向上再走一步，不是它的对立面。

**保留窗口 N 是全局单一常量，与[努力档位](../../CONTEXT.md)正交。** 档位已经驱动两处（步数预算与模型 reasoning effort），再挂第三处会让「改一个档位」的后果不可预测——[ADR-0011](./0011-model-input-configuration-is-versioned-and-persisted.md) 那轮已用同一条理由否掉「四档映射两份提示词」的多对一错配。更实质的是：N 的最优值由**引用忠实度**决定，档位由**任务复杂度**决定，两者不是同一个自变量；耦合之后评测也无法单独扫这一维。

N 的首版取值**是拍的，不是算的**，与 ADR-0005 的分节阈值同类，由评测的引用忠实度校准，两者应一并校准。

### 占位符带 URL 与标题——知情接受重读代价

业界「工具结果可重取，所以安全可清」的前提是**重取便宜**。本项目不成立：ADR-0005 的运行内记忆化运行结束即死，**跨运行没有任何记忆化**。模型看到指代想要正文，就会重新读同一个 URL，真走一次供应商、真花一次钱。

仍然带 URL 与标题。判据是 ADR-0005 那条原则的**可行动性**内核——告知之所以有价值，是因为模型知道后能做点什么。带 URL 时「我读过这三篇，需要哪篇就重取哪篇」是可行动的；只给计数时，模型除了道歉或**凭残存印象编造引用**别无选择，而后者正是引用忠实度指标要判死的行为。重读花钱属于「只追踪不限制」已经接受的那类代价，编造引用不是。

因此**不需要注入任何合成消息**：指代本身就是如实告知，消息表原样不动。这与 ADR-0001「UI 的折叠由查询时过滤实现，而不是靠不存」是同一手法，也不违反 ADR-0008「不写指令性文案」。

## 第 2 层：原子单位是一次已完成的运行

丢弃以「一次已完成的运行产出的整块」为单位——助手消息、它发起的全部工具调用、全部配对结果同生共死。半切会凭空造出悬空。两条永不删：

**当前正在进行的这次运行整块不删。** 理由不止「因果链会断」：运行中途删自己的消息就是**运行中途改记忆**，正是 ADR-0001 推翻的 checkpointer 那套的近亲，也违反 ADR-0008「输入序列在开跑前确定、Runner 必须纯」。

**第一次运行的整块永不进入删除候选。** 业界有先例（LibreChat 给首条用户消息最高优先级），本项目另有两条自己的理由：[ADR-0012](./0012-the-auxiliary-model-never-writes-to-the-message-table.md) 定了标题由首条用户消息生成——它定义了这个会话是什么；且会话公开共享、任何访客可续聊，**首条是别人的问题**。

### 压缩是失败的持久后果，不是失败的恢复路径

第 2 层怎么被触发，与 [ADR-0015](./0015-upstream-errors-pass-through-unclassified.md) 正面相撞：那份 ADR 定死了上游错误原文透传、**不为上游错误建立分类映射**，以及重试判据是「对面有没有回话」——超窗错误恰恰是上游回了响应的，不该重试，而我们又不许把它分类识别出来。第 2 层因此永远触发不了。

**决定：超窗那一轮照常失败、原文透传给用户；这次失败在会话上留下一个削减计数，下一轮重建时丢弃最旧的一块已完成运行。** 不重试、不分类，只是「失败一次之后会话自动瘦身一次」。

代价知情接受：公开 demo 上，一个长会话的第一次超窗会以**一次可见失败**呈现，重发一次才通。这符合 ADR-0008 已确立的观测哲学——被掐断的运行就显示被掐断，比在背后猜错误类型偷偷重试诚实。

## 被否决的方案

**任何形式的摘要。** ADR-0005 已判弱模型摘要死刑（弱模型主导的有损压缩，主模型据此写出的引用对应不上任何一段真实原文）。换主模型来摘要更贵，且**同样**毁引用忠实度——问题从来不在摘要器的能力，在于原文被替换成了转述。

**供应商的服务端上下文管理**（Anthropic 的 `context_management`、OpenAI Responses 的 `truncation: "auto"`）。三条：

其一，**三协议能力不对齐到无法用同一套语义表达**——一个是「清旧工具结果」，一个是「从中间砍」，`openai_chat_completions` 是零。[ADR-0014](./0014-the-model-is-chosen-by-the-user-never-by-the-system.md) 说的「协议各自建模互不翻译」指的是**协议差异**；而「喂多少历史」是**领域决策**。让它随协议漂移，等于同一个会话换个端点档案就换一套记忆规则，可复现性当场没了——ADR-0015 刚以同一条理由否掉「失败换模型」。

其二，**它在实际部署形态下会静默失效**。[ADR-0016](./0016-the-model-list-is-discovered-and-persisted.md) 那轮实测中转站连官方 `capabilities` 一个字段都不透传，一个 beta 特性走中转的生存概率只会更低；而 base URL 可自定义是硬需求，实际部署就是走中转。做成「直连生效、走中转静默失效」是最坏形态。

其三，**它让「模型实际看到了什么」不可由我方推导**。评测的回放层要断言同输入产出逐字节相同的事件流，ADR-0011 把模型输入的配置面全部版本化落库；服务端悄悄删掉几条工具结果，这两条同时失效，**而且失效得没有痕迹**。

**排除清单（`exclude_tools`）做成配置项。** 业界判据是「可重取 vs 有状态」：文件读取、API 响应、搜索结果可按需重取，安全可清；记忆工具输出、凭据、累积任务上下文有状态，必须保护。[ADR-0006](./0006-tool-failures-split-into-external-and-programmatic.md) 之后本项目锁死的两个工具**全部可重取、零有状态**，排除清单恒为空——这条判据白送，不该留一个永远为空的配置项。

**清理滞后带（`clear_at_least`）。** 它在业界存在，是因为按 token 触发会让边界抖动、反复砸缓存写。本项目按**次数**滑动，窗口每步整齐移动一格，没有抖动可言。参数模型借形不借全。

**照搬业界五层压缩体系。** 逐层映射后本项目只占三格：重排以命中缓存那层**不适用**（序列本就按 `seq` 确定性重建、天然稳定前缀，且中转站的缓存透传未验证），分段摘要与子代理摘要两层**已被否**。抄成五层就是造三个从未被调用过的空壳，与地图划出的「简历驱动开发」红线同类。

值得写下来的是**为什么别人需要那两层而我们不需要**：编码 agent 的工具输出**不可重取**——bash 输出依赖当时机器状态、grep 结果依赖当时文件内容、编辑是副作用，重跑不保证同结果，所以它只能摘要保存。本项目两个工具的键都是 URL，幂等可重取，**可以直接丢**。三层不是偷懒，是架构约束在源头把两层消掉了。

继承下来的是它的**原则**而不是层数：永远优先最轻的干预。而本项目最重的那层是免费地丢，不是花钱起子代理摘要。

## 后果

**掩蔽发生在重建投影时，消息表原样不动。** 落点是 [ADR-0007](./0007-backend-is-split-by-capability-not-by-layer.md) 定的 `conversation/service.py` 重建函数，与悬空修复同处一地。

**掩蔽窗口随迭代滚动，删除不在运行内发生。** 前者是确定性的：给定同一份消息序列与同一个 N，每一步的窗口位置完全可推导。

**评测回放的录制内容必须包含每次响应的输入 token 数。** 第 1 层的预算用真值触发（见 [ADR-0018](./0018-there-is-one-token-yardstick.md)），而回放层跑的是录好的响应、零网络零数据库；录制少这一个字段，窗口位置就不可复现，「逐字节相同」的断言当场破——**且它会静默地破**，回放照样跑，只是断言的东西悄悄变了。

**生效的保留窗口值记在跨度上，不建版本表。** ADR-0011 那两张表存在是因为内容是长文本且事后不可重算；一个整数记在跨度属性上就完全可重算，不满足建表判据。它应与提示词版本标识、工具集版本标识并列出现在 trace 查询接口里。

**`app` schema 的会话行新增一个削减计数。** 这是本决策唯一的 schema 增量。

**压缩决策全程可观测，这是本项目相对业界实现的真实差异点。** 别家的多层压缩对用户是黑的——看不到当前在哪一层、清了什么、省了多少。本项目把每次掩蔽做成跨度上的一等公民（清了几对、哪几个来源、掩蔽前后的实测输入 token 差值、触发原因），并把保留窗口做成评测自变量，产出「压缩强度 × 引用忠实度 × 成本」曲线。业界没有一家给出过公开可复现的这条曲线。

**掏空诱发的重读率是需要测的量。** 它是「跨请求缓存要不要做」这个悬而未决问题毕业的前提——在此之前那仍是过度设计。
