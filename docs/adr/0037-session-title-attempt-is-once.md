# 会话标题自动生成资格由业务数据原子认领

历史实现由首条消息触发的主运行发起标题生成（ADR-0012）；独立 HTTP 调用（ADR-0036）下，同一会话可能收到并发尝试。原先以 `title IS NULL` 决定调用、再以 `title == fallback` 决定写入，无法区分人工改成相同文字与未经修改，刷新或清空标题也可能重新开放调用。

**决定：`app.session` 保存 `title_generation_eligible`、`title_generation_claimed_at` 与 `title_manually_edited`。** 只有随首条用户消息新建的会话获得资格；迁移时已有行与旧代码创建的行默认不合格。首条用户消息与 fallback 在同一事务提交；模型调用开始前，认领针对未删除、合格、未认领、未人工改名会话执行单条条件 `UPDATE`；成功提交后才调用模型。模型调用期间不持有该事务或行锁，也不因失败、超时、取消或未应用而撤销认领。

人工改名无论内容是否变化，都原子记录修改并关闭应用资格。模型结果只有在已认领、仍合格、未人工改名、未软删除时条件写入；不根据标题文字推断修改状态。独立标题 HTTP 响应只携带条件写入后实际生效的值；已删除会话不应用标题。`fallback_title` 是首条消息列表标题的唯一规则来源，`auxiliary` 输出仍不写消息表。

本决定保留独立 HTTP 调用（[ADR-0036](./0036-title-generation-is-an-independent-session-call.md)）所需的一次性认领与人工改名保护，不改变旧跨度或历史统计口径。迁移只添加字段，不删除数据或依赖 downgrade；旧镜像仍可对新 schema 运行（ADR-0031）。
