# 评测夹具冻结在工具供应商层，不在 ModelPort

评测（[#24](https://github.com/EllisYuan/ChatAgents/issues/24)）要回答「新提示词/新工具集是不是真的更好」，这要求同一批输入下**模型必须是活的**——[ADR-0025](0025-replay-happens-at-the-model-port-not-the-http-transport.md) 把测试回放的冻结点上移到 `ModelPort`，正是为了让 Runner 零网络零数据库跑完；评测如果复用这同一个冻结点，冻结的正是要被测量的那个东西，问题当场变成「录下来的旧答案和录下来的旧答案比」，什么都测不出来。

**决定：评测夹具冻结在[工具供应商](../../CONTEXT.md)层（Tavily / Jina Reader），不在 `ModelPort`。模型调用打真实网络，工具调用命中录制夹具，键是数据集里的场景 ID，不是模型生成的查询字符串本身。**

## 为什么键是场景 ID 不是查询字符串

模型是活的，就意味着它每次生成的 `web_search` 查询词都可能不同——同一条数据集场景在旧提示词下生成的查询词，换了新提示词后完全可能是另一句话。若夹具按查询字符串精确匹配，[双跑](../../CONTEXT.md)在新版提示词下会打空整批夹具，退化成打真实网络，评测当场变得不可复现也烧穿预算。

场景 ID 是数据集自己定义的、与提示词版本正交的标识；录制时按场景枚举全部合理候选查询词的响应，运行时命中该场景下已录制的任意查询即可命中，不要求逐字相同。

## 已知代价

- 数据集新增一条场景，需要先打一次真实网络录制才能进入夹具库，不是纯配置操作。
- 供应商换算法/换索引导致同一 URL 内容漂移不会被感知——夹具冻结的就是某一时刻的供应商响应，这是特意接受的：评测比较的是「提示词/工具集变了答案会不会更好」，供应商本身的漂移是另一个维度，混进来会让同一次双跑里出现两个变量。

## 后果

- L2 测试回放（`ModelPort` 边界）与评测夹具（工具供应商边界）是两套录制物，互不复用，物理上分开存放。
- 评测在 CI 里跑法本身不触网；数据集扩容时的录制脚本才触网，且只在录制那一次。
