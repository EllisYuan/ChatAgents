# token 只有一个口径：上游计费口径

[ADR-0004](./0004-tools-are-capabilities-providers-are-implementations.md) 把工具层切成三段，其中编排层是一个纯函数，职责是「规范化、切章节、**计数**、渲染」；[ADR-0005](./0005-long-documents-use-progressive-disclosure.md) 的分节阈值单位是 **token**。两者合起来要求项目里存在一个 token 计数器，但**没有一份决策说过它是什么**。[ADR-0017](./0017-old-observations-are-masked-not-summarized.md) 的保留窗口预算是第二个需要它的地方。补上这个洞。

**决定：全项目只有一个 token 口径——上游响应报告的输入 token 数（[用量](../../CONTEXT.md)三态中的 `COMPLETE`）。本地估算器的职责不是「数 token」，是「预测上游会数出多少」。**

## 为什么不是一个精确的本地 tokenizer

因为不存在这样的东西，四条独立证据：

**Anthropic 不公开本地 tokenizer**（Claude 4 之后再没发过）。第三方可视化工具用的是逆向 BPE 近似加手工调整。

**官方计数端点自己都说是估算。** 文档原文是 "The token count is an **estimate**"，且返回值会包含供应商为系统优化注入的 token。连供应商自己的端点都不精确。

**同一家的不同代次差约三成。** 同一段文本在 Claude 4.7 前后的计数差异约 30%。不存在「Claude 的 tokenizer」，只有「某一代的 tokenizer」——而 [ADR-0016](./0016-the-model-list-is-discovered-and-persisted.md) 定了模型清单运行时发现、用户可填任意标识，我们连它属于哪一代都不知道。

**计数端点只有一个协议有。** `anthropic_messages` 有，两个 OpenAI 协议都没有对应端点。用它就是又一次三协议不对齐，撞 ADR-0017 已定的判据；走中转站是否可用亦未验证。业界那些「对 Claude 也准」的多模型计数库，内部正是**调这个网络端点**——它们没有解决问题，只是转发了问题。

## 为什么真值比任何 tokenizer 都好

上游响应里的输入 token 数是**那个模型对那次请求的实际计费口径**。它不是近似，它就是账单本身，比供应商自己的计数端点还准（后者自称估算）。[ADR-0014](./0014-the-model-is-chosen-by-the-user-never-by-the-system.md) 已经给了它语义（用量三态），[ADR-0002](./0002-business-and-observability-share-a-database.md) 之下它已经是物化真列，取用零成本、零额外网络调用、零 tokenizer 依赖。

## 一把尺，两种读数来源

两处用的是同一个口径，差别只在真值可得性：

- **保留窗口的预算**：上一轮响应的真值 + 本轮新增部分的校准后估算。
- **分节阈值**：纯校准后估算——那段文本还没进过任何模型，没有真值可用。

真值承担九成以上的量，估算只承担这一轮新增的增量，而增量恰好是我们自己产生的（工具结果全文就在编排层手里）。**误差被压到增量上，不落在全量上。**

这也是**对齐**的解法。若两处各用一套口径，同一个数字在两处含义就不同：一篇文档在工具层被判「未超阈值、全文返回」，进了上下文按真值算却可能超出——两个阈值互相不可比、无法互相推理。把估算器的目标重新定义为「预测上游口径」之后，两处读的是同一把尺。

**分节阈值那里要的是确定性，不是精确度。** ADR-0005 已明写那个阈值**是拍的、不是算的**；用一个存在系统偏差的估算器去比一个拍出来的阈值，误差被阈值本身的任意性淹没。真正不能丢的是「同一段文本永远数出同一个数」——评测回放的逐字节可断言性建立在这上面。

## 后果

**本地估算器全项目只有一处实现**，分节阈值与保留窗口预算共用它。

**它自校准。** 观测侧已有每次调用的实测输入 token 数，按模型分组算「实测 ÷ 估算」即得该模型的偏差系数。这是纯查询层工作、零 schema 变更——与 [ADR-0003](./0003-span-table-follows-phoenix.md) 说「成本随时可补算」是同一手法。「估算器有实测校准，且校准数据来自本项目自己的 trace」是本项目相对业界实现的一处真实差异，值得写进对外文档。

**校准系数作为入参传进编排层，编排层不得自查模型。** 系数按模型分组，而 ADR-0004 定了编排层是纯函数、[ADR-0007](./0007-backend-is-split-by-capability-not-by-layer.md) 定了工具执行上下文落 `agent/`。由执行上下文携带系数传入，纯函数性质与「工具是能力、供应商是实现」两条都保住。

**`PARTIAL` 与 `UNAVAILABLE` 态没有可用真值**，退化为全量估算并在跨度上标记口径。缺失的用量**不得以 0 表示**——那是 ADR-0014 的硬规矩，此处不开口子。

**系统提示词不需要单独记账。** 上游数的是整个请求，真值天然包含它。[ADR-0010](./0010-the-system-prompt-is-run-configuration-not-conversation-memory.md) 定了重建序列不含系统提示词、由服务层另行注入，那笔账在真值路径上根本不存在；仅在退化为全量估算时才需显式加上它的估算值。

**预算是滞后一轮的。** 这不是缺陷而是分工：常态层要的是体积控制，不是超窗的精确防守——后者归 ADR-0017 的第二层，由上游错误驱动，因为唯一准确的超窗信号就是那个错误本身。**任何 token 数都不触发丢弃。**
