# 工具失败分两类：外部的交回模型，自己的抛出来

工具炸了，异常给谁？把所有异常一律 `except Exception` 转成给模型的字符串是常见的省事做法，代价是**线上有 bug 但表现为"模型今天有点笨"**——模型会绕着缺陷走，而日志里什么都看不见。这是最难查的一类故障。

**决定：按"这是外面的问题，还是我们的问题"分两类处理。**

| | 例子 | 处理 |
|---|---|---|
| [外部失败](../../CONTEXT.md) | 超时、429 限流、404、目标站拒绝、供应商 5xx | **不抛异常**，转成结构化的工具结果交回模型 |
| [程序错误](../../CONTEXT.md) | 参数校验不过、缺配置、代码 bug、密钥未配置 | **抛出**，中止运行并上报 |

第一类是 agent 韧性的核心：一次检索超时不该让整场对话崩掉，模型完全可以换个查询、换个 URL，或如实告诉用户"这个站点读不到"。第二类则必须响亮地失败——把自己的缺陷伪装成外部失败，等于主动放弃发现它的机会。

## 失败照样进跨度

**[外部失败](../../CONTEXT.md)必须记为错误[跨度](../../CONTEXT.md)，哪怕模型优雅地绕过去了、最终答得很好。** 那次失败是[观测事实](../../CONTEXT.md)。否则你看到的是一次漂亮的运行，底下藏着三次超时。

## 重试

只重试超时、连接错误、429 与 5xx；`400` / `401` 这类客户端错误重试是白烧钱。退避用指数加抖动。

**重试不消耗步数。** 步数记的是模型的决策次数，不是 HTTP 请求次数——重试三次仍是一步。

**每次尝试记一个子跨度**，而不是只在父跨度上记 `attempts=3`。掩盖失败是本项目最不该做的事，且"第一次超时 4 秒、第二次成功"这类时序信息只有分开记才留得下。

## 超时不受努力档位影响

[努力档位](../../CONTEXT.md)管"做多少"，超时管"等多久才认定它坏了"，两件事。`xhigh` 不意味着愿意等六十秒——一个卡住的 HTTP 请求在任何档位下都是故障，不是努力。
