# 上游错误原样透传，只重试没回话的调用

**决定：端点返回了 HTTP 响应，这次调用就算「打通了」——错误原文原样交回上层，本项目不解析、不映射、不重试。只有压根没收到响应（连接失败、连接重置、读超时）才重试。**

## 为什么不按状态码判可重试性

原本准备走行业惯例：429 与 5xx 退避重试，4xx 直接失败。实测（2026-08-11，`api.ellisyuan.com`，cliproxy）把这条打死了：

| 真实原因 | OpenAI 路径 | Anthropic 路径 |
|---|---|---|
| 模型标识不存在 | **502** `internal_server_error` | **502** `api_error` |
| 上游凭证不可用 / 冷却中 | **503** `auth_unavailable` | **404** `not_found_error` |
| 欠费 | **402**，体带裸 `code` 字段 | **429** `rate_limit_error`（"Usage credits are required"） |
| 密钥无效 | **401**，体是**裸字符串** `{"error":"Invalid API key"}` | — |

三处硬伤：**429 是欠费不是限速**（退避一万次也不会成功）；**502 是模型标识写错**（同上）；**同一个原因在两个协议下报两个不同的码**（404 与 503）。

按状态码重试，结果是每次欠费都白烧三轮退避；而且这张对照表是**某一家中转站的转译规则**——换一家就失效，与「base URL 可自定义」这条硬需求直接冲突。

「对面有没有回话」则不依赖任何人的转译，是这里唯一稳定的判据。

## 为什么错误不分类

错误体的形状本身就不统一：401 是裸字符串，502 是 OpenAI 的嵌套形状，402 带一个规范里没有的顶层 `code`。要从中解析出「这是密钥问题还是额度问题」，只能靠关键词匹配，而那同样是给某一家中转站写的适配。

所以本项目**不设错误分类词表**：原文照登。用户看到的是上游说的话，不是我们对上游说的话的猜测。

## 已知代价：原文可能包含上游的内部信息

实测抓到的一条真实错误原文：

```
auth_unavailable: no auth available (providers=claude, model=claude-3-5-haiku-20241022);
check Claude auth/key session and cooldown state via /v0/management/auth-files
```

它把中转站的**内部管理端点路径**写在了错误消息里。本站全局公开无鉴权，因此这行字会显示给每一个访客。

**这个代价是知情接受的**，与「demo 完全开放、接受风险」的既定立场一致。记在这里是为了将来有人觉得「怎么把内部路径漏出去了」时，能查到这是一个决定而不是一次疏忽。密钥本身不在此列——它靠 `SecretStr` 与那条扫[跨度](../../CONTEXT.md) `attributes` 的 CI 断言把守，与错误透传是两条独立的路径。

## 后果

- 重试只覆盖「没收到响应」，退避与次数上限对所有端点一视同仁，不按厂商配置。
- 重试呈现为 trace 里的子跨度；最终失败按 [ADR-0008](./0008-a-run-emits-domain-events-not-wire-frames.md) 的分界走——流开始前用 HTTP 状态码，流开始后走 `RunFailed` 事件。
- 密钥有效性**无法提前校验**（除非专门发一次探测请求，那是每次运行多一次往返去买一个更漂亮的错误码），因此 401 几乎必然是**流后失败**。
- 错误消息里带上[密钥来源](../../CONTEXT.md)——公开 demo 里最容易搞错的就是「我以为用的是我填的密钥」。这是本项目自己加的一个字段，不是对上游错误的分类。
