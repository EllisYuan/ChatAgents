# 聊天界面是唯一的控制台

地图的既定约束写着「把 trace / token / 成本 / eval 揉进聊天界面本身——单一界面，不做产品面 + 控制台双层分离」。那是一句方针，不是一个形态。[#18](https://github.com/EllisYuan/ChatAgents/issues/18) 用两版丢弃式原型把它变成具体形态，本决定记录选中的那个。

**决定：内联手风琴 + 三层密度。**运行详情就地长在每条回答下方，不开抽屉、不设常驻侧栏、不做模式开关。

## 四个候选，否掉的三个各有各的理由

| 候选 | 否掉的理由 |
|---|---|
| **抽屉**（点摘要行从右侧滑出） | 详情与它解释的那条回答**在空间上断开**。看一眼就得开一次、关一次，读者不会连着看第二条。 |
| **常驻侧栏**（右侧一栏恒在） | 访客躲不开。它把「工程读者可以深入」变成「所有人必须面对」，且长会话里那一栏永远只显示当前运行，与上方滚动的历史对不上号。 |
| **双模式开关**（聊天模式 ⇄ 工程师模式） | 它把「同时服务两种人」偷换成「让人先声明自己是哪种人」。访客不会去点工程师模式，于是门面消失；技术读者点进去看到的又是一个跟别处没两样的 trace 控制台——「揉进聊天界面本身」这句话当场落空。**两个模式就是两层分离，只不过分离发生在时间上而不是空间上。** |

内联手风琴留下的代价是展开时页面会长高、把下方内容推走。接受：这正是「就地」的物理含义，且展开是读者自己按下的。

## 三层密度

信息密度是本票最难的一问——普通访客只想聊天，技术读者想看内部机制。答案不是折中，是**分层**：

| 层 | 触发 | 内容 |
|---|---|---|
| **第 0 层** | 永远可见 | 回答正文；一行摘要 `▸ 2 步 · 1.8k tok · 3.1s`；一行 `▸ 思考 3.2s` |
| **第 1 层** | 点摘要行 | 按 `STEP_*` 分组的跨度时间轴、工具结果卡片、本次运行配置区 |
| **第 2 层** | 点单个跨度 | 该跨度明细：模型标识、角色、双向 token、耗时、错误原文 |

第 0 层是这个作品集的门面：**一眼就能看出这不是个套壳聊天框**，同时它只有一行，访客可以完全无视。往下每一层都是读者主动按出来的。

### 摘要行只有三个数字

步数 · token · 耗时。不放成本、不放密钥来源、不放 main/aux 拆分。

- **成本不落数字**，只在版面上留位。[ADR-0003](./0003-span-table-follows-phoenix.md) 定了成本不落库、当前阶段只统计 token 不做价格换算，而价格矩阵（中转站折扣、自定义单价）仍是地图上未毕业的一片雾。真要画出美元数字就得连带把那片雾一起决了，那不是本票的范围。**留位不留数**：将来填数字只改文本不改结构。
- **密钥来源不上界面**，见 [ADR-0029](./0029-the-ui-never-mentions-the-key.md)。
- **main / aux 不在摘要行拆**。辅助模型绝大多数时候只是标题生成（[ADR-0012](./0012-the-auxiliary-model-never-writes-to-the-message-table.md)），为一个恒定的小数字在每轮多摆一个数不划算。它的用量计入摘要行总数，拆分在第 1 层的时间轴上——aux 调用是主运行下的兄弟跨度，看得见。

## 骨架实时，数字收尾

跨度骨架随流长出：`STEP_*`、`TOOL_CALL_START/END` 一到就画，读者能看见 agent 正在干活。**token 与耗时等运行收尾**（`chatagents.usage`）**再一次落定**。

理由是流式用量本就不可信：[ADR-0009](./0009-the-wire-format-is-ag-ui-over-sse.md) 与模型接入层定了用量三态，中途的数是半截的，让它随流跳动等于把一个不准的数字做成界面上最抢眼的动效。

**断连时摘要行写 `▸ 2 步 · 用量不完整 · 3.1s`**——不显示 0，也不显示估算值。[ADR-0008](./0008-a-run-emits-domain-events-not-wire-frames.md) 定了客户端断连就地停，[ADR-0023](./0023-absent-fields-say-why.md) 定了这类「曾经会有」的缺失必须说明原因，这里是它在呈现层的第一个实例。

## 运行配置区：不可展开的东西不要放进可展开的东西里

[ADR-0011](./0011-model-input-configuration-is-versioned-and-persisted.md) 把提示词与工具集版本化，跨度里只存指代 `{system_prompt@<version_id>}`，且系统提示词对用户不可见不可改。[#16](https://github.com/EllisYuan/ChatAgents/issues/16) 因此给本票留了一道视觉难题：**「看得见但点不开」很容易招人点**，做成折叠块就是在承诺「点我有内容」，而点开什么也没有。

解法是不要把它放进可点开的东西里。第 1 层的跨度时间轴**下方**是一块平铺的参数表，不属于那棵树：

```
本次运行配置
提示词    research-agent@20260810T093000-a3f8c1d2e9b0
工具集    toolset@20260805T140000-9e21f0aacb31
努力档位  xhigh
保留窗口  最近 6 对观察
输入序列  已丢弃最旧 2 轮（累计削减 2）
```

表格单元格的形态承诺的是「这是一个值」，没人会去点它。版本标识分两段排版——`research-agent` 正常字重（人认的那半段），`@20260810T093000-a3f8c1d2e9b0` 降一档灰度且等宽（机器认的那半段）；点击复制全串，不展开。

这一块同时消化了四处交办：[#16](https://github.com/EllisYuan/ChatAgents/issues/16) 的两个版本指纹、[ADR-0023](./0023-absent-fields-say-why.md) 定的运行级字段（版本标识与保留窗口）、努力档位回显、以及削减计数进详情不进列表。它们的共性正是「运行级、不可展开、只是一个值」——**共性决定了它们该在同一块里**。

**努力档位有两个值，不要混**：输入框旁的四档切换器说的是「下一轮用什么」，配置区回显的是「这一轮用了什么」。两者会不一致，且不一致时读者必须能看出来。

## 跨度树由两处拼出，规格就是唯一的防线

[ADR-0009](./0009-the-wire-format-is-ag-ui-over-sse.md) 定了工具跨度不自己发（`TOOL_CALL_START/END` 自带 `tool_call_id`），模型跨度走 `chatagents.span`。[ADR-0022](./0022-one-handler-touches-one-schema.md) 又硬约束服务端不合并两侧。于是**前端必须处理这个不对称**，合并规则写死如下：

1. 以 `STEP_*` 事件切分迭代边界，一个迭代一组；
2. 迭代内，`chatagents.span` → 模型跨度；
3. `TOOL_CALL_START` 建工具跨度、`TOOL_CALL_END` 收尾、`chatagents.tool_result` 填卡片字段、`TOOL_CALL_RESULT` **只提供渲染文本**（它在 AG-UI 语义里是消息表那条 tool 消息，不是卡片数据源）；
4. 同一迭代内两侧跨度**按事件到达顺序排，不按时间戳排**——流内顺序即真相，重排会让并发工具调用的兄弟关系失真。

[#17](https://github.com/EllisYuan/ChatAgents/issues/17) 定了前端弱测试（无 Vitest / RTL / Playwright），并点名这段合并逻辑是全项目最容易出 bug 且零自动化覆盖之处。**代偿是把上面四条写成 `frontend/src/features/trace/` 的规格文档，并要求它与实现同 PR 修改**——写文档不是引入测试框架，不违背那条决定；而在没有测试的地方，一份说得死的规格是仅剩的防线。

## 上下文压缩只进 trace，不进对话流

观察掩蔽与整轮削减都不在对话流里留任何痕迹。

**关键事实：削减丢的是模型输入序列，不是消息表。**[ADR-0001](./0001-messages-are-the-single-source-of-truth.md) 定了消息表是唯一事实来源，行一直在。所以读者往上滚**什么都没少**——在流里画一条「本轮已被压缩」的分隔条是在制造一个并不存在的损失感。

- **掩蔽**落在被掩蔽的那条工具跨度上：结果卡片照常完整显示，旁边一行低调标注「模型现在只看到标题与 URL」。「读者看得见、模型看不见」的落差要一眼看懂，就得让两者出现在同一个视觉单元里。
- **削减**落在运行配置区那行「输入序列」。

**掩蔽状态由后端记录，前端只读。**它在重建那一刻是确定的，属于观测事实；让前端按保留窗口 N 自己数，等于把同一条规则实现两遍，而其中一遍零测试覆盖——正是上一节要避开的东西。落点是运行级跨度的 `attributes`，不动 REST 契约的形状。

## 其余落定项

- **工具结果卡片**的字段来自 `chatagents.tool_result`，显示标题、供应商域名、相关性分（细进度条）、耗时。**favicon 不取远程**，用域名首字母配稳定色块——公开站上给每个搜索结果发一个第三方请求，等于把访客看了什么泄露给第三方域名。这是隐私取舍不是美术选择。
- **重试与失败不折叠**：失败的那次作为紧邻的子行保留，标红并给出上游原文（守 [ADR-0015](./0015-upstream-errors-pass-through-unclassified.md) 的原文透传），重试成功的那次排在它下方。把失败藏起来，「降级与重试可见」这个卖点就没了。
- **并发工具调用**画成同一迭代下的兄弟跨度，左侧竖线归组，时间轴上并排——[ADR-0004](./0004-tools-are-capabilities-providers-are-implementations.md) 的并发默认开启在界面上就是这个样子。
- **推理摘要**收起态占一行 `▸ 思考 3.2s`，点开看正文。默认展开会让老会话重开时一大片「已过期」占住主位（[ADR-0023](./0023-absent-fields-say-why.md) 的 `aged_out`）。辅助模型的推理不在流里，界面不为它留位。
- **可用性状态的视觉语言**分三形态，读者不读文字也能分辨：结构性不存在 → **什么都不显示**；已老化 → **一行灰度注释 + 时钟图标，无边框无色块**；错误 → **红色描边 + 上游原文**。「已过期」被读成「出错了」是 [#18](https://github.com/EllisYuan/ChatAgents/issues/18) 点名要避免的，色彩语义是这里唯一靠得住的区分手段。
- **两个降级态天生分层，不需要两套视觉语言**：档案 `unavailable`（env 缺失）压根不进选单，读者看到的只是一个更短的选单，不加解释——站长没配 key 是内部信息；清单为空（发现失败）则档案**在**选单里而模型清单是空的，配手填输入框、`fallback` 标记与「重新获取」。一个在档案层、一个在模型层，混不了。
- **模型标识不在已获取的清单内**时在输入框下方当场标出「不在清单中，仍可发送」，不阻断——[ADR-0016](./0016-the-model-list-is-discovered-and-persisted.md) 定了发现失败是提示性而非中断性。
- **标题的流式过渡**：侧栏该行先显示「新会话」加一条骨架微光，`TitleGenerated` 到达时淡入替换，不做打字机——它与正文增量交错出现，打字机会让两处同时在动。会话列表项仍只有三个字段（[ADR-0013](./0013-the-session-list-shows-business-facts-only.md)），不做仪表盘。
- **eval 不进聊天界面**，但站点里有一个只读展示面（关于页 / 页脚）。[ADR-0026](./0026-tests-and-evals-are-two-systems.md) 定了测试与评测是两套体系，评测跑的是离线数据集、与单次对话无关，做成会话级会把它拉成产品功能。放哪几个数字取决于 [#24](https://github.com/EllisYuan/ChatAgents/issues/24) 尚未裁定的指标。

## 后果

- 前端目录里出现 `features/trace/`，其规格文档与实现同 PR 修改，是那段客户端合并逻辑仅有的防线。
- 观测侧新增一个运行级 `attributes` 键，记录本次运行输入中被掩蔽的观察。
- 摘要行为成本预留版面。价格矩阵那片雾毕业时，只填数字不改结构。
- 会话列表与聊天界面之外**不再有第二个界面**——没有控制台页、没有 trace 页、没有工程师模式。
