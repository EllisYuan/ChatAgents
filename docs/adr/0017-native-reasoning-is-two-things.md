# 原生推理是两样东西，不是一个字段

[#15](https://github.com/EllisYuan/ChatAgents/issues/15) 的实测在响应体里抓到一个规范外字段 `reasoning_content`：`gpt-5.4` 返回一句摘要，gemini 路径返回整段思维链正文。当时记下的判断是「同一个字段名，两种截然不同的量级」，于是本题被写成一道三选一——采不采、存[消息](../../CONTEXT.md)表还是存[跨度](../../CONTEXT.md)、发不发前端。

**这个题面是错的。** 三家协议加两份规范，四处独立地把它建模成两样东西：

| | 往返载荷 | 显示摘要 |
|---|---|---|
| Anthropic Messages | `thinking.signature`、`redacted_thinking.data` | `thinking` 正文（需 `display: "summarized"`） |
| OpenAI Responses | reasoning item 的 `encrypted_content` | `summary` 数组（需 `reasoning.summary`） |
| AG-UI | `ReasoningEncryptedValueEvent`、`ReasoningMessage.encrypted_value` | `REASONING_MESSAGE_CONTENT`、`ReasoningMessage.content` |
| OpenInference | `tool_call.reasoning_signature` | `message_content.type="reasoning"` + `.text` |

**决定：按这条缝切开，两样东西各归各的表。**

## 往返载荷进消息表

Anthropic 官方："when you return tool results, you **must** pass the thinking blocks from the assistant message back to the API, complete and unmodified"。改动过的块一律 400，连顺手过滤掉 `redacted_thinking` 都会 400。而本项目是 ReAct Loop，**每一轮都是 tool-use turn**。

所以在 `anthropic_messages` 上，它不是「要不要采」，是不采就跑不通。而 [ADR-0001](./0001-messages-are-the-single-source-of-truth.md) 定的消息表存「完整模型视角序列」、每轮从库里重建——它就在那个序列里。

存法是**按[协议](../../CONTEXT.md)原样存放的不透明附件**：不解析、不翻译、原样进原样出。这与三协议各自建模互不翻译同构，不透明块正是「不翻译」的极端情形。

OpenAI Responses 侧官方措辞是 "highly recommend" 而非强制，但 `store: false` 下 reasoning item 默认带 `encrypted_content`，形态与处置完全一致，不为它单开一条路径。

## 显示摘要进跨度

摘要不进消息表，理由与 [ADR-0010](./0010-the-system-prompt-is-run-configuration-not-conversation-memory.md) 把系统提示词挡在消息表外完全相同：**模型自己看不见它。** 官方原文 "The thinking model does not see the summarized output"，摘要由另一个模型生成，且 "subject to change"。它不是对话记忆。

破这一次例，ADR-0001 那句「完整模型视角序列」就变成「模型视角序列，外加一点别的」，下一个想往里塞东西的人就没有可被拒绝的理由了。AG-UI 把 `content` 与 `encrypted_value` 挂在同一个 `ReasoningMessage` 上，是最有诱惑力的反例——但 [ADR-0009](./0009-the-wire-format-is-ag-ui-over-sse.md) 已定领域层不吃 AG-UI 的类型，它是线格式，不是存储模型。

摘要落跨度 `attributes`，用 OpenInference 现成的键（`message_content.type="reasoning"` + `.text`），**一个自造 key 都不需要**，[ADR-0003](./0003-span-table-follows-phoenix.md) 那句「导出到自托管 Phoenix 零摩擦」保住。一处提醒：Phoenix 当前的 Output Messages 面板尚不渲染 reasoning，只在原始 `attributes` 里可见——规范有，UI 渲染滞后。

## 两个协议都主动开摘要，Chat Completions 一概不采

Anthropic 的 `display` 与 OpenAI 的 `reasoning.summary` 都是 opt-in，**且都不额外计费**（官方："You're charged for the full thinking tokens generated by the original request, not the summary tokens"），唯一代价是 Anthropic 侧首个正文 token 稍晚——`omitted` 的卖点正是更快的 TTFT。本次改造的核心叙事是把 trace 揉进聊天界面本身，模型自己的推理是这条叙事上最直观的一块，而它免费。

Claude Opus 5 / Sonnet 5 / Fable 5 上 thinking **默认已开**、`display` **默认 `omitted`**，所以「主动开」是必须做的动作，不是可选优化。

**`openai_chat_completions` 路径一概不采**——既不往返（协议里没有这个位置）也不显示。那个 `reasoning_content` 是中转站自造的，且用的是生态**已弃用**的旧名：vLLM 已改叫 `reasoning`，OpenRouter 与 Google 走 `reasoning`，LibreChat 至今挂着一个 open issue，标题就是「hardcoded to deprecated `reasoning_content` field」。消费它就是把某一家中转站的私有转译规则写进代码，与 [ADR-0016](./0016-the-model-list-is-discovered-and-persisted.md) 拒绝那 33 个倒写别名是同一判据——而这次连「至少它是标准的」都谈不上。代价是同一个模型在两个协议下推理表现不一致，但协议本就是用户显式选定的[端点档案](../../CONTEXT.md)属性（[ADR-0014](./0014-the-model-is-chosen-by-the-user-never-by-the-system.md)）。

## 推理 token 是用量，进真列

Anthropic 给 `usage.output_tokens_details.thinking_tokens`（流式下只在最后一个 `message_delta` 上出现），Responses 给 `output_tokens_details.reasoning_tokens`。二者都是输出 token 的子集，都按输出计费。

ADR-0003 已经画好了那条线：真列（用量与分账维度）永久保留、`attributes` 过期清空，「成本与用量的历史统计因此永不失真」。**推理 token 就是用量**，且是纯[观测事实](../../CONTEXT.md)而非[推算](../../CONTEXT.md)。放进 `attributes` 等于宣布「历史上多少 token 花在思考上」这个数会老化失真，而它恰恰是本项目核心叙事里最有说服力的一个数。

于是 ADR-0003 的物化真列从五个变六个。缺失时记 **NULL 不记 0**，与[用量三态](../../CONTEXT.md)同一条纪律；Chat Completions 路径按上一节恒为 NULL。

## 线上只发摘要那一半

AG-UI 的七个 `REASONING_*` 里发五个：`REASONING_START` / `REASONING_MESSAGE_START` / `REASONING_MESSAGE_CONTENT` / `REASONING_MESSAGE_END` / `REASONING_END`。

不发 `REASONING_MESSAGE_CHUNK`：ADR-0009 已定三个 `*_CHUNK` 一律不发，理由是那是给不知道消息边界的生产者准备的便利形态，而这里边界清清楚楚（Anthropic 的 `content_block_start`/`stop`、Responses 的 summary part 事件）。

不发 `REASONING_ENCRYPTED_VALUE`：**AG-UI 设这个事件是假定客户端可能持有会话状态并回传**，而 ADR-0001 定的是服务端持有消息表、前端从不构造模型输入。往前端推一个它永远用不上、也永远不会送回来的加密大块，是纯带宽浪费，且等于把往返载荷摊给公开站的每一个访客。

**这修订 ADR-0009**：「33 个事件类型只发 15 种」改为**只发 20 种**，其中「`REASONING_*` 留位不发」一条作废——它当时的理由是「现在发等于先定一个没人产出的格式」，现在有产出了。

摘要的消息标识**独立派生**（`uuid5(运行标识, 迭代序号, "reasoning")`），不复用同一次调用产出的助手消息标识。复用会让 `TEXT_MESSAGE_CONTENT` 与 `REASONING_MESSAGE_CONTENT` 打在同一个标识上，前端拿到两串 delta 却只有一个标识，只能靠事件类型硬拆，把本来正交的两个通道又粘回去。派生是纯函数，ADR-0009 那条「同输入产出逐字节相同的事件流」不受影响；代价是流里会出现消息表中没有对应行的标识——这正确，因为它本来就不是一条消息。

## 后果

**老会话重开时看不到推理。** 摘要随 ADR-0003 的分级老化清空，往返载荷按 [ADR-0018](./0018-the-round-trip-payload-lives-for-one-run.md) 跨运行不回放。这与 ADR-0010 定的系统提示词对用户不可见是同构取舍，但更容易被察觉：用户上次见过、这次没了。因此**只有这一种「没有推理」需要留痕**——协议不支持、模型这次自己选择不思考、中转站没透传，三种一律静默：用户从没见过就不会误判，且后两者在 ADR-0014 定的不做能力探测之下本就无法区分，硬要分就是给一个探不到的东西编分支。

**`auxiliary` 角色的推理只记不发。** 标题生成（[ADR-0012](./0012-the-auxiliary-model-never-writes-to-the-message-table.md)）走 `auxiliary`，其摘要不进流——标题不是一条消息，`REASONING_*` 的消息标识在界面上无处可挂。但跨度必须记：[ADR-0013](./0013-the-session-list-shows-business-facts-only.md) 已定标题的用量计入运行总账，推理 token 是输出 token 的子集，不记就是漏账。

**`display` 与 `reasoning.summary` 不进 [ADR-0011](./0011-model-input-configuration-is-versioned-and-persisted.md) 的版本化体系。** 它们只改变返回形态、不改变模型输入——官方明说 `signature` 在两种 `display` 下完全相同——因此不影响评测基线。

**中转站透不透传未经实测。** 本 ADR 的结论全部由三家协议的公开规范推出，不依赖任何一台中转站；实际部署上能否看到推理是一条待验证事实，而「看不到」的降级语义已在上面定死，验不验都不改变代码形态。
